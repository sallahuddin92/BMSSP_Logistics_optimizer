# Task 15 Phase 6 — isolated original-binary engineering smoke

ENGINEERING_SMOKE_ONLY · NOT_TASK15_COLLECTION · MEASUREMENT_ELIGIBLE_FALSE

This separate executable implements one fixed engineering smoke campaign. It does
not import the dormant production worker/native operation modules or change
`production_gate()`. The original controller, adapter, algorithm and protocols stay
unchanged. It reuses only pure frozen-protocol, artifact identity, import-transaction
and counter-name helpers. There is no scientific execution or routing capability.

## Fixed scope

`run.py run-fixed --output /FRESH/EXTERNAL/EVIDENCE` creates one exclusive directory,
claims each launch durably, and starts one CPython 3.11 arm64 child per variant using
`-I -B`. Its interpreter is the existing verified local CPython 3.11.15 environment;
there is no executable override. Variants come only from the frozen v1.3 protocol.
Each private child claims an exclusive file and validates its inherited nonce.
Repeated claims and existing output directories are rejected. There is no retry.

The only graph is vertices [0,1,2,3,4,5] and the seven user-prescribed directed edges
10–16, embedded in `smoke/contract.py`. The only calls are `solve(0, profile=False)`
and `solve(3, profile=False)`, once each. `Budget` rejects extra or reordered source
requests. No arbitrary graph, source, binary path, benchmark, warmup, calibration,
collection or profiler argument exists. Tests use fake objects and a disposable
SIGKILL process; they do not execute additional native solves.

Expected distances and paths are independently embedded from the Phase 6 request:

| Source | Distances in [0,1,2,3,4,5] order | Required path vertices / edge IDs |
| --- | --- | --- |
| 0 | [0,2,5,6,8,+Infinity] | [0,1,2,3,4] / [10,11,13,14] |
| 3 | [+Infinity,7,10,0,2,+Infinity] | [3,4,1,2] / [14,16,11] |

The smoke checks exact little-endian binary64 bits, source identity, graph storage,
algorithm identity, directed orientation/weights, unreachable target 5, required
work counters, materialization and disabled profile call counts. Expectations are
not generated by BMSSP or Dijkstra. No reference algorithm runs.

## Loading and evidence

Preflight rejects ABI/architecture mismatch, global module contamination, loader
environment injection and active trace/profile hooks. It hashes originals before
import; the exact-path loader rechecks path/hash and mapped extension UUID after
import. Baseline and candidate never share an interpreter. The loaded dependency
path, LC_ID_DYLIB install name, arm64 architecture and LC_UUID identify each actual
system library. Both variants must report identical dependency identities. These
are observed loaded-image identities, not a newly approved frozen OS-library hash
allowlist. No standalone SHA is invented for shared-cache library files.

The `binary` identity object in receipts is deliberately the static pre-import
snapshot returned by the reused helper; its NOT_LOADED fields describe that stage.
The journal's IMPORT_VERIFIED event (loaded module path), dependency records, native
construction/query events and parent exit receipts establish actual runtime state.
Removing sys.modules is not claimed to unload an extension; process exit is the
isolation boundary.

Results are dropped before the next solve. Weakrefs check object death where
supported, with accurate null/limitation reporting otherwise. Graph and engine
references are dropped at the end. Child exit status, PID, parent reaping and raw
stdout/stderr are retained. This does not prove all native allocations were
reclaimed or establish general leak freedom.

No T0/T5 clock exists in this executable. Native query_seconds/preprocessing_seconds
are removed immediately from returned diagnostic dictionaries before any retained
copy or serialization. Profile duration fields are also discarded. The original
binding still computes its internal timings; none is retained/analyzed. The parent
uses only a fixed subprocess timeout to contain crashes/hangs, without recording
query or process elapsed durations. Counters support correctness checks only.
There are no speed or overhead claims.

Every JSON receipt/event is marked with the three engineering-only labels and
measurement_eligible=false. Launch claims, events and receipts use exclusive or
append-only files with fsync. COMPLETED.json hashes the immutable campaign payload.
Exact loader errors and formatted tracebacks are retained; failure never triggers
a second campaign. A Python audit hook forbids opening any original frozen road
input in each actual child. The executable has no road loader.
