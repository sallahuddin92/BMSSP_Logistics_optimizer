# EXPLORATORY_BMSSP_PERFORMANCE — E1 design

This is a fresh, nonconfirmatory native experiment. Task15 remains blocked and its protocol, harness, approvals and original artifacts are untouched. No historical timings or historical binary equivalence are used.

Baseline engine: commit 5e8b11b4db8a0883969e7fe1405b048f419d7f07, exported into an external source/build directory. An identical external CMake project hook compiles this experiment's native-only driver against baseline and candidate. Python bindings, sanitizers and allocation interception are OFF for latency builds. Explicit process-local CLT/SDK, arm64, deployment26.0, Release settings are shared. Diagnostic/sanitizer runs are separate from all latency runs.

Inputs are the three archived GraphML identities and their previously exported directed native text, retaining vertex/edge IDs, all parallel edges and binary64 decimal round trips. All100 source occurrences are correctness workload; first10 occurrences are performance workload. Independent GraphML/native tuple comparison precedes acceptance.

Before choosing an optimization, run baseline native regressions, all100 positions/graph exact BMSSP-versus-native-Dijkstra distance checks and all-target directed path validation. Keep complete interleaved BMSSP/Dijkstra binary64 vectors. Run a small baseline pilot (3 measured repeats/source, 1 warmup), separately enabled built-in profiling, and uninstrumented native CPU sampling. Profiled timings cannot substitute for ordinary timings; choose one hypothesis only after these observations.

Primary controlled matrix after the hypothesis: 10 blocks, 5 measured repeats/source/engine/build/block =50 observations/source/condition. Each condition is a fresh process. Four conditions: baseline BMSSP, candidate BMSSP, baseline Dijkstra, candidate Dijkstra. Block orders alternate forward/reverse, balancing baseline/candidate and algorithm precedence. Graph order rotates; source order rotates over the frozen first10 positions. One untimed warmup/source/process. No concurrent benchmark/build/test workloads. Persist plan and every invocation, individual sample and failure.

Identical primary boundary: steady_clock immediately before solve, endpoint immediately after solve returns. Internal workspace cleanup is included; result destruction, fingerprinting, full correctness checks, serialization and graph preparation are outside both algorithms' timing. Prior result is destroyed before the next start. Native BMSSP query_seconds is diagnostic only. Graph construction and degree reduction are separate. RSS is Darwin whole-process peak bytes, reported separately from diagnostic C++ allocation counts/requested bytes; neither is confused with query-only live memory.

Statistics: nearest-rank p50/p95/p99 of individual samples, separately by graph/condition and per source. Report BMSSP/Dijkstra ratios and baseline/candidate ratios. Pair by graph, block, source occurrence and repeat. Report block-level effects and deterministic block-resampling uncertainty (seed20261112), with only10 blocks; no Task15 estimands, thresholds or approvals. Tails are descriptive, especially per-source n50. Do not delete outliers. Flag every p95/p99 increase and investigate substantial or inconsistent regressions using all raw observations and order/host metadata.

Decision: ACCEPT_OPTIMIZATION only with exact correctness and relevant native/memory-safety gates, reproducible benefit across fresh processes and roads, and no unjustified substantial tail, memory or reliability regression. Otherwise REJECT_OPTIMIZATION or INCONCLUSIVE. No minimum speedup is invented. No second optimization hypothesis is permitted. Evidence-driven uncertainty takes priority over acceptance.
