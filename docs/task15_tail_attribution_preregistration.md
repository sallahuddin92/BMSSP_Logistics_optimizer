For a spike, define paired excess as candidate minus baseline at the same original query position. A diagnostic flag uses wall > max(1.5 × frozen historical position baseline NR median, that median + 10 ms); every other observation remains in the distributions and raw outputs. No future source filtering is allowed. A larger wall-minus-thread-CPU gap establishes an estimated off-CPU component only. Runnable off-CPU scheduler intervals are needed to distinguish descheduling from blocked allocator/lock waits. Thread CPU increases establish on-CPU execution-time changes, which can still arise from memory stalls, frequency or core placement.

For strong event attribution require at least three directly linked events in at least two sessions, validated timing/trace overlap, at least 80% accounting of excess without nested double counting, and a mechanism-specific control that changes matched excess by at least 50% with its descriptive interval excluding zero. H2 uses its separately defined CPU ratio/session rule. Where these requirements are unavailable or conflicting, report WEAKLY_SUPPORTED or UNRESOLVED. No unplanned full factorial is implied: strong interacting-cause claims can remain unresolved and require a later amendment.

### 6. Measurement Architecture

| Boundary | Definition / observation |
| --- | --- |
| T0 | worker request parsed, source identified, prior Query fully destroyed outside new timed span; immediately before wrapper solve call |
| T1 | binding source conversion and native numeric/source validation complete; conceptual entry marker (B only) |
| T2 | existing native start point immediately after original_source lookup, before k/t and workspace construction |
| T3 | existing query_seconds endpoint after projection/validation, before workspace and temporaries destruction; marker-only B |
| T4 | engine.solve returned, workspace cleanup complete; returned ShortestPathResult remains live; no claim that output result destruction occurred |
| T5 | binding Query response returned to worker, before fingerprints/serialization/IPC; not FastAPI/network response |
| T6_optional | returned Query destroyed after fingerprints outside timing; recorded in B/C separately, excluded from T0..T5 |

T1 and T2 are adjacent conceptual entry/start boundaries in the present engine. Cohort A can directly see only external T0/T5 and existing legacy native duration. B adds marker-only observations in external diagnostic source copies at the exact engine/binding sites; T1/T4 are wall-only, T2/T3 have wall and same-thread CPU, and outer T0/T5 additionally have process CPU and thread user/system split when calibrated. The graph, recursion, frontier, numeric checks, algorithms and result lifetimes must not change. Production sources remain untouched. These diagnostic binaries get their own hashes and code-generation comparison; B measurements never substitute for A latency.

A request is worker-local, not network/FastAPI latency. Destroy prior Query results, extracted distance/path lists and warmup returns before T0. Retain the new result through T5, then fingerprint and destroy it outside timing. This removes Task 14's previous-result decref from the timed assignment and changes the estimand deliberately; do not pool old/new data. T4 completes workspace/local cleanup but retains the output result; T6 optionally observes output destruction separately. Existing T3 excludes workspace destruction.

Use monotonic raw tick endpoints, cached Mach conversion, checked arithmetic, same-thread CPU clocks, stable PID/TID and globally unique query IDs. Store counter read order and wall apertures: endpoint samples are not simultaneous. At native endpoints bracket the CPU read by wall reads. At phase boundaries record monotonic/continuous/UTC anchors for trace joins and sleep detection. Do not join submillisecond events by UTC alone.

Save T5−T0, T3−T2, T2−T0, T4−T3, T5−T4, same-window thread CPU, process CPU, user/system splits where valid, and CPU/wall ratio. Wall−CPU is a derived estimate with endpoint error; preserve negative rounding values and flag invalid precision rather than clamping. Process CPU can include other threads and exceed wall. On-CPU CPU time includes memory stalls, while native elapsed also includes descheduling. Allocation requests/bytes, cumulative outermost request time, maximum observed request/free interval and stacks exist only in separate C/D scopes.

No clocks/calibration or diagnostic recording were run now. Future fixed calibration: 10,000 empty endpoint groups, eight fresh paired calibration clusters, original eight warmup positions × 20 repetitions/region, hooks off/on counterbalanced. B gate: zero API failures, p99 read aperture ≤100 μs; median endpoint cost ≤2% and p99 cost ≤5% of historical small NR p50 (1.788208 ms); differential median instrumentation ratio change ≤0.005. Under 100 μs, fine attribution is precision-limited. Calibration samples are never part of A/B distributions and no overhead is subtracted from query latency.

One predefined fallback removes outer process/split calls, retaining wall and own-thread CPU only, then performs one fixed calibration again. If it fails, B attribution is unavailable and cannot support a CPU claim; A may proceed as its own approved cohort. C records all outermost requests in preallocated buffers (2,000,000 events/query cap), with recursion guards and no per-event stack unwinding. Buffer loss invalidates that diagnostic metric for the entire paired diagnostic block. Timed new/delete coverage excludes arbitrary C malloc/mmap/other-thread allocations unless separately observed. Never call the old request-count probe an allocator latency measurement.

### 8. Statistical Preregistration

Primary estimand is Cohort A candidate/baseline NR quantile ratio for each graph and protocol over the fixed, equally weighted100-position workload and 32 trials. Protocols and cohorts are separate factors and are never pooled. Report p50/p95/p99/min/max, per-process median/p99, per-session distributions, per-original-position paired differences/ratios, source-level consistency, trial/region/startup order views, and all extremes. NR is `sorted[ceil(p*n)-1]`; conventional medians, if used, receive a separate label.

Within each original position, across 32 trials report NR median, NR MAD, p95−p50 and max. For a distinct-source summary first pool that source's repeated positions within each trial then give each of96/100sources equal weight. Do not use the old 800 rows or new 3200 as independent inference units. Ratios are null if their baseline denominator ≤max(1 ns,10 effective clock quanta); report signed differences and retain raw data. CPU/wall needs a wall interval above10 clock quanta. No imputation, denominator clipping or dropping near-zero sources.

Bootstrap: 100,000 repetitions, NumPy PCG64 seed 15062026, non-studentized percentile intervals. Draw eight sessions with replacement, then four paired trial clusters within each selected session occurrence and protocol. Keep all 100 positions, both variants and all three regions together in each sampled cluster. Use the same session draw across protocols/regions and same within-protocol draws across regions. Recompute quantiles, ratios and source summaries; do not resample individual query rows. Runtime NumPy version is locked before collection.

Confirmatory family has ten decisions: six p50 region×protocol ratios and four p99 medium/corridor×protocol ratios. Two-sided family alpha 0.05 uses Bonferroni alpha 0.005 each, percentile endpoints 0.0025/0.9975 (99.5% individual intervals). Ordinary descriptive95% endpoints 0.025/0.975 are also reported. A separately declared secondary H2 family covers six B native-threadCPU p99 region/protocol ratios at family alpha 0.05, Bonferroni percentile endpoints 0.0041666667/0.9958333333; this is corroboration only and not a production gate. There is no joint FWER guarantee across these two families. The session-stratified sensitivities use the same respective confirmatory quantile bounds; readiness requires conservative agreement of both upper bounds. These approximate bootstrap intervals have limited coverage guarantees with eight sessions and rare tails; no unconditional production-population inference is claimed.

Sensitivity is fixed:100,000 session-stratified paired-trial resamples with seed 15062027, leave-one-trial-out, leave-one-session-out, per-session/batch and AB/BA summaries, historical-order adjacency views, equal-source weighting. P1/P2 interaction is log R_P1−log R_P2, with common session draws; order interactions compare matched first/second strata. C/D hypothesis diagnostics use descriptive95% cluster intervals/seed 15062028; those intervals do not provide eight multiplicity-adjusted causal proofs. Report all hypotheses, including unfavorable/unsupported ones. No outlier deletion, winsorization, p-value fishing or favorable sensitivity replacement.

Invalidate only genuine predetermined protocol failures: wrong binary/graph/list, missing/duplicated position, schedule/warmup violation, crash/error/corrupt record, verified machine sleep/reboot, or profiler/build/test overlap in A. Apply to the complete paired cluster/all regions/both variants; preserve every attempt. Correctness mismatch stops the experiment. No automatic replacement or favorable-result retry. Any missing required A cluster prevents confirmatory closure in v1; describe valid data, then amend explicitly before extra collection. High load, thermal warning, power change and slow latency alone never qualify. Trace loss affects the complete paired diagnostic metric/block, not ordinary A observations.

### 12. Protocol Limitations

Capability listing and installed API definitions establish feasibility, not successful runtime access. Profiling privileges, trace export fields/loss, effective CPU accounting precision and perturbation remain preflight/calibration gates. Optional unavailable D modes use explicit UNSUPPORTED outcomes and fixed fallbacks; they do not force an invented causal conclusion. Without validated scheduler/core/PMU fields, corresponding attribution remains unresolved. In particular system/cluster powermetrics data cannot establish exact query frequency, and no public hard P/E isolation is assumed.

Fixed road/source lists do not represent every logistics workload. Eight sessions limit uncertainty even with 32 process trials/protocol; hierarchical bootstrap is approximate and extreme tails may remain underpowered. Warmup, persistent graphs, source history, IPC and compound protocol differences remain factors. Randomized source order tests whether variability persists under improved scheduling; it is not a literal original-order replay. Historical adjacency is analyzed descriptively. Further ordered replay or factorial controls require amendments; no post-hoc expansion is hidden in v1.

C/D perturb allocator, cache, power and scheduling state. Diagnostic off/on controls measure some perturbation but cannot prove transferability to uninstrumented A. Predefined background/cache interventions may affect multiple mechanisms, so strong cause labels remain conditional. New data never change stopping, exclusion or acceptance criteria. A ready plan does not resolve F2, declare p99 superiority or claim a new performance result.
